## §0 Decision

Design B ships: the copy is an isolated step in `scripts/update_season.py` on its own connection, run before and after the ingest subprocess, with failures deferred past `_push_step`, and the backfill is the same function behind `--snapshot-only`. Three grafts from A: a real `ingest --check-schema` gate (ingest's `--dry-run` returns at ingest.py:880, before `assert_schema` at :889); `update_season.py --dry-run` as the mandatory last gate, because `diff()` runs `whole_fingerprints(remote)` before the dry-run return (push_remote.py:392-393, :607) so a missing f1_push grant surfaces there; and no FK to `events`, so history survives a schedule renumber. Product grafts: the scored row is the greatest `computed_at` strictly before the race session's `start_utc`, the empty state is parametrised, and the title-odds table is captioned as a nightly reconstruction (title.py:630-651 DELETEs and re-simulates every `after_round`) and keeps its ranges and prior badge.

Panel claims checked against the code: `_run` keeps a 4000-char tail (update_season.py:70-72), so A's "snapshot FAILED" grep is fragile and B's in-process accounting is right. `psycopg.Error` derives from `Exception`, not `OSError`; the retry loop (push_remote.py:664) catches only ConnectionError/OSError/RuntimeError, so a permission-denied SELECT inside `diff()` escapes `push()` and crashes the script with a traceback — loud in the gate, production untouched on a nightly, but R15 unpublished. `neon_migrate.sh` applies `0012_push_role.sql` as its step 7 and ROTATES the four role passwords to the exported values: run it only with the passwords remote.env and Vercel already carry. `pg_default_acl` holds only `f1_web=r` (verified locally). The ask-manifest exclusion is not free (§3). `tests/test_push_remote.py` has 10 tests (the census note "9" is stale). R15 races Sat 26 Sept 11:00Z (session 440, 0 results); the nightly at 03:20 local runs before that (07:20Z) and again the night after.

## §1 Tables (Drizzle owns the DDL; migration 0012; Python never issues DDL)

- `preview_snapshot_round`: the 21 `preview_round` columns verbatim, same builders and types (`computed_at timestamptz NOT NULL`, no default — always the preview's own value), then `snapshot_at timestamptz NOT NULL DEFAULT now()` (audit only: when the copy ran; never a key, never shown as the preview's date). PK `(year, round, computed_at)`. No FK, no CHECK (no FK to `events`: a renumber must not cascade-delete history; no FK to `assumption_sets`: the id is a copied fact).
- `preview_snapshot_order`: `year, round, computed_at` (the round's `computed_at`, copied in), then the 11 remaining `preview_finish_order` columns in their order (`assumption_set_id, driver_id, expected_position, pos_p10, pos_p90, p_win, p_podium, p_points, theta, dnf_rate, draws`), then `snapshot_at`. PK `(year, round, computed_at, driver_id)`. One FK: `(year, round, computed_at) → preview_snapshot_round ON DELETE CASCADE`, so the catalogue's `parents` orders the push round-then-order and "no order row without its round row" holds by construction. Neither has `session_id`, so `classify` reaches the WHOLE_TABLES rule.
- Drizzle (`web/db/schema/companion.ts`, after `previewBacktest`; re-declared builders, not a spread — a spread would carry `defaultNow` onto `computedAt`):
  ```ts
  export const previewSnapshotRound = pgTable("preview_snapshot_round", { /* previewRound's 21 builders, minus .references() and .defaultNow() */,
    snapshotAt: timestamp("snapshot_at", { withTimezone: true, mode: "string" }).notNull().defaultNow() },
    (t) => [primaryKey({ columns: [t.year, t.round, t.computedAt] })]);
  export const previewSnapshotOrder = pgTable("preview_snapshot_order", { year, round, computedAt: timestamp("computed_at", { withTimezone: true, mode: "string" }).notNull(),
    /* the 11 previewFinishOrder builders, minus .references() */, snapshotAt },
    (t) => [primaryKey({ columns: [t.year, t.round, t.computedAt, t.driverId] }),
      foreignKey({ columns: [t.year, t.round, t.computedAt], foreignColumns: [previewSnapshotRound.year, previewSnapshotRound.round, previewSnapshotRound.computedAt], name: "preview_snapshot_order_round_fk" }).onDelete("cascade")]);
  ```
  `index.ts` already re-exports `./companion`. DDL intent of 0012: two CREATE TABLE, two PK, one FK. Inspect the generated SQL before committing (L1).
- `f1lab/frames.py`: two entries placed before line 564 so `EXPECTED_COLUMNS` derives them and `assert_schema` owns them: `TABLE_COLUMNS["preview_snapshot_round"] = TABLE_COLUMNS["preview_round"] + [("snapshot_at", "timestamptz")]`; `TABLE_COLUMNS["preview_snapshot_order"] = [("year","int"), ("round","int"), ("computed_at","timestamptz")] + [c for c in TABLE_COLUMNS["preview_finish_order"] if c[0] not in ("year","round")] + [("snapshot_at","timestamptz")]`. Not in `RACE_TABLE_ORDER` / `SPRINT_TABLE_ORDER` (not per-session). A local DB without 0012 now makes `ingest --check-schema` refuse — the guard L3 relies on.

## §2 The write

- Where: NOT inside `recompute_preview` (preview.py:762-767). A failure there fails the companion step, marks the ingest run failed, ingest exits 1 (ingest.py:837), `failures` fills and `_push_step` SKIPS the push (update_season.py:264-266) — the one outcome forbidden on R15 night. Instead: `f1lab/preview.py: snapshot_sql() -> tuple[str, str]` (pure; column lists from `frames.EXPECTED_COLUMNS`) and `snapshot_preview(conn) -> dict` (runs both statements, returns `{"round": n, "order": m, "computed_at": max_or_None}`); `scripts/update_season.py: _snapshot_step(label: str, deferred: list[str]) -> None`.
- Exact SQL (column lists rendered from EXPECTED_COLUMNS at call time; `r.computed_at` is copied, `now()` is never written):
  ```sql
  INSERT INTO preview_snapshot_round (<the 21 preview_round columns>)
  SELECT <the same 21> FROM preview_round
  ON CONFLICT (year, round, computed_at) DO NOTHING;
  INSERT INTO preview_snapshot_order (year, round, computed_at, <the 11 order columns>)
  SELECT o.year, o.round, r.computed_at, <o.<the 11>>
  FROM preview_finish_order o JOIN preview_round r USING (year, round)
  ON CONFLICT (year, round, computed_at, driver_id) DO NOTHING;
  ```
- Idempotency: the key is the preview's own `computed_at` (one value per recompute, preview.py:735); a second run inserts 0 rows; `snapshot_at` takes its default only on the row's first insert. The JOIN gives each order row its round's `computed_at` (`preview_finish_order` has none).
- Isolation: `_snapshot_step` opens its own `psycopg.connect(DSN)`, runs `with conn.transaction(): SET LOCAL lock_timeout = '5s'; SET LOCAL statement_timeout = '60s'; counts = preview.snapshot_preview(conn)`, closes in `finally`. It runs strictly before or after the ingest subprocess, never concurrently with the DELETE in `recompute_preview`; the lock file and `_other_writers()` already forbid a second f1lab process.
- Placement in `main()`: step 0 `_snapshot_step("before", deferred)` right after `failures: list[str] = []` (captures whatever preview exists, e.g. the 18 Sept one on Saturday); step 1b `_snapshot_step("after", deferred)` right after the ingest `_run` returns, whatever its rc (captures the fresh recompute). Neither runs under `--dry-run` (writes nothing) or `--push-only`.
- Logging: `snapshot(before|after|backfill): +N round, +M order rows (computed_at max=…)` / `snapshot(after): nothing new` / `snapshot(after): FAILED <ExceptionType>: <redacted message>`.
- Failure accounting without blocking: `_push_step` is gated on `failures` alone, so the step never touches it. `main()` keeps `deferred: list[str]`; after `_push_step` returns and before the `=== done` line, `failures.extend(deferred)` — the done line reads `FAILURES: snapshot(after) failed: …`, exit 1, output/update_season.log has it, the push was unaffected.
- Backfill = the same function: new flag `--snapshot-only` = `_other_writers` check, lock, `_snapshot_step("backfill", deferred)`, done line, `1 if deferred else 0`; no ingest, no push, no telemetry. L5 runs it; the second run's `nothing new` is the idempotency proof.
- Quiet nights: every successful `ingest --season` recomputes the companion (ingest.py:818-828) with a new `computed_at`, so a quiet night still appends 9 + 198 rows of identical content (~7k rows by season end; a content-hash dedupe is a follow-up, not now). A manual `--recompute-companion` between nightlies destroys the current preview: RUNBOOK says run `--snapshot-only` first.

## §4 Ledger UI (`/accuracy`, section `id="ledger"`, title "What we said before each race", after `PointsBandSection`, before `id="limits"`; nothing existing moves)

- Query `getPreviewLedger(year)` in `web/lib/queries/ledger.ts` (new), `cached("accuracy.getPreviewLedger", …)` (REVALIDATE_SPEC; purged by the push hook). Rule: per `(year, round)` with any snapshot, the scored row is the snapshot with the greatest `computed_at` **strictly before** `sessions.start_utc` of that round's `kind = 'R'` session (session rows exist for scheduled rounds: 440 = R15). A snapshot computed after the race started stays in the table and is never scored — this is what lets the captions say "before each race" even on the night a race is stored without results (`_SCHEDULED_SQL`, preview.py:679-685, drops a round only once RESULTS exist, so a partial ingest recomputes a post-race preview). Rows: every round with a scored snapshot; the result columns are filled when `results` exist for that session, else a dash.
- Columns of the captioned DataTable: Round · Preview dated (`computed_at`, never `snapshot_at`) · Our top three (expected order, `p10–p90` beside each) · Actual top three (`classified_position` 1–3) · Rank agreement (Spearman of `expected_position` vs `classified_position` over CLASSIFIED drivers — `classified_position ~ '^[0-9]+$'`; `D`/`R`/`W` are text) · Claimed (that snapshot's `backtest_spearman`) · Bands held (share of classified drivers with `pos_p10 ≤ actual ≤ pos_p90`; the cAcc9 convention, so it is comparable to the claimed figure) · Claimed (`backtest_coverage`) · Not classified (count, so nothing is hidden). Pure helpers in `web/lib/accuracy/ledger.ts`: `spearman(pairs)` (average ranks for ties; `n < 2 → null`), `coverage(rows)`, `topThree(rows)`.
- Captions (`web/lib/accuracy/captions.ts`, verbatim, slots in braces; pre-formatted strings such as `"9 previews"` are built by a small helper in the component, as cAcc17 does):
  - `C_LED_1` = "These are the previews as they stood before each race, copied the night they were computed and never edited afterwards. A preview computed after a race had started is kept in the record but is never scored here."
  - `cLed2(races, first)` = "{races} on record since {first}. The first copy was taken by hand from a preview computed before the copying step existed; every later copy is written the night it is made. One race is an anecdote, and this table only starts to mean something once it is long enough to disagree with the backtest above."
  - `C_LED_3` = "The backtest rows elsewhere on this page are predictions for races that were already stored, scored out of fold. Each row here was written down before its race and cannot have seen it; the claimed figures beside it are what that same preview said about itself."
  - `cLedEmpty(previews)` = "No race has been run since the record began. {previews} on record, waiting for the race."
  - `C_LED_EMPTY_NONE` = "The record has not received its first copy yet. It is written the night the next update runs."
  - `C_LED_4` = "Title chances after each round, recomputed from the stored results up to that round with the current model. These are not the figures as first published: a model change rewrites every column. The range beside each figure is its uncertainty, and a figure marked prior belongs to a driver with no completed race at that point, so it rests on the prior rather than on results."
- Empty states, in order: zero rows in `preview_snapshot_round` for the season (the deployed site until N4 or the first nightly) → `C_LED_EMPTY_NONE`; snapshots but no round with results → `cLedEmpty("9 previews")`. Both render through DataTable's `emptyReason`.
- Title-odds table (`title-record`, same section, cut if late): `getTitleOddsLine(year)` = the five drivers with the highest `p_title` at the latest `after_round`, columns `after_round` 1..N, cell `p_title` as a percentage with `p_title_lo–p_title_hi` beneath, a "prior" badge when `is_shrunk_to_prior`; caption `C_LED_4`. Nothing new is stored; no chart. Horizontal scroll stays inside the table (DataTable's region).
- This week, honestly: until N4 the section shows `C_LED_EMPTY_NONE`; after N4, `cLedEmpty("9 previews")`. On Sunday 27 Sept, after ingest + push: exactly one scored row — R15, preview dated 18 Sept (or Sat 07:20Z if the Saturday nightly ran after Friday's qualifying), actual top three, one Spearman against a claimed 0.603, one coverage figure against a claimed 0.947, a count of retirements. Rounds 16–23 are on record but unscored.
- Never claimed: that a snapshot is sealed or provable (IDEAS §3 #11; no hash, no third-party record); that `preview_backtest` rows are forecasts (C_LED_3); that title odds were "published at the time" (they are rebuilt nightly); that coverage counts retirements as misses (it is scored over classified drivers and says how many were not); that one row is evidence (cLed2). Forbidden words absent: live, real-time, up to date, updated every hour.

## §6 Safety before Saturday, and the rollback

| Failure mode on the first unattended push | What happens | Excluded by |
|---|---|---|
| Neon lacks 0012 | `_same_shape` → `SCHEMA MISMATCH: table … missing remotely`, push REFUSED (rc 2), `failures`, exit 1, production unchanged, R15 unpublished | N2, proven by N3 |
| Migration ledgers differ (local at 0012, Neon not, or the reverse) | `check_schema` → `SCHEMA AHEAD/BEHIND`, same outcome | N2 + L2, proven by N3 |
| f1_push has no grant on the new tables | `whole_fingerprints(remote)` raises `psycopg.Error` inside `diff()`, uncaught by the retry loop, script dies with a traceback before apply; production unchanged, no fixture republish | N2 step 7, proven by N3 (the dry run runs that SELECT) |
| Local DB not on 0012 | `assert_schema` refuses (`table preview_snapshot_round is missing`), ingest exits 2, push SKIPPED | L2, proven by L3 (`ingest --dry-run` never reaches `assert_schema`) |
| Snapshot step raises (lock, timeout, anything) | caught in `_snapshot_step`, `deferred`, push proceeds, exit 1 with the reason in the done line | design (§2) |
| Snapshot step waits on a lock | `lock_timeout 5s` → the row above | design (§2) |
| `gen_ask_schema` aborts on an unclassified base table | CI sync test red; nothing at runtime | L4 |
| `publish_fixture` ledger-count check fails | fixture not republished (warning only, :304-309); push already done | L2 |
| The launcher never reaches Python (`PermissionError` on `.venv/pyvenv.cfg`) | nothing runs at all, any design | N6 — pre-existing, not this change |

- Rollback (one hunk): revert the `update_season.py` change (steps 0/1b, `--snapshot-only`, `deferred`). The migrated, classified tables stay and are inert: unchanged content → equal fingerprints → `nothing to do`; the page shows `cLedEmpty` from whatever was copied. Never drop the tables in a hurry — that needs a migration on both sides and the manifest again.
- `--dry-run` proves: lock, `_other_writers`, classification, `_same_shape`, migration parity, the f1_push SELECT on both tables, the push plan. Only a real run proves: the local schema (L3), the copy (L5 IS that run) and the Neon apply (N4 is the rehearsal; otherwise Saturday's push is the first).
